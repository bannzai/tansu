# SQLite のデータの持ち方

tansu のデータは SQLite 1 ファイル (既定 `~/.tansu/tansu.sqlite`、環境変数 `TANSU_DB` で差し替え) にある。利用者のデータベースとプロパティの定義 (メタスキーマ) も同じファイルの中に持つ。

- **物理スキーマの定義は 1 箇所**: SQLite のテーブル定義 (CREATE TABLE) は `src/db/` のモジュールにだけ書く。コアの関数以外 (CLI・MCP・HTTP API・画面) は SQL を書かず、コアの関数を呼ぶ
- **マイグレーションは起動時に自動で当てる**: 物理スキーマの変更は、番号付きのマイグレーション (`src/db/migrations/`) として足し、`user_version` で適用済みを判定して起動時に順に当てる。利用者にスクリプトの実行を求めない。当てたマイグレーションは書き換えず、変更は新しい番号で足す
- **利用者のデータベースの定義はデータとして持つ**: 利用者が `db create` / `db schema` で作る表とプロパティは、物理テーブルを増やさず、メタスキーマのテーブル (データベース・プロパティ・行・値) のデータとして持つ。利用者の操作で DDL を実行しない
- **ファイルを直接開く入口を増やさない**: Web 画面・MCP・castle の skill は CLI か HTTP API を通して読み書きし、SQLite ファイルを別プロセスから直接開かない (同時書き込みの競合と、スキーマの知識の分散を防ぐ)
- **書き込みは冪等にする**: 同じ入力で 2 回実行しても行が増えない (取り込みの元ファイルと項目名のような自然キーで upsert する)
- **テストは一時ディレクトリの DB を使う**: `TANSU_DB` をテストごとの一時ファイルにし、実際のホームディレクトリに書かない
